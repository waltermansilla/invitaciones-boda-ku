IDEA: Crecimiento / viralidad + cupones referidos (panel)
========================================================
Fecha: julio–agosto 2026 (actualizado con estructura)
Estado: estructura en código + muestra Sofía & Mateo.
NO son instrucciones de “activar en todos los clientes”.


================================================================================
SWITCH POR CLIENTE
================================================================================

  rsvpPanel.referidos: true | false
  - Si falta o es false → sistema de referidos OFF (sin teaser ni activación).
  - Requiere rsvpPanel.enabled + panelId (contrataron panel).
  - Solo se muestra con link personal del invitado (?i=codigo).

  Copy / UX en sección RSVP:
    sections[type=rsvp].data.promo { teaser, modal, discountPercent, validityDays }


================================================================================
CÓDIGO POR INVITADO
================================================================================

  Formato: {prefijo}{numero}
    - prefijo = novia+novio o XV (ej. sofiamateo) → SOFIAMATEO08
    - número = secuencial por prefijo al PRIMERA activación (01, 02, …)
  Activación = primera vez que el invitado abre el modal “Ver cupón”.
  Vencimiento = fecha de activación + 30 días (validityDays, default 30).
  Reabrir el modal = mismo código y misma fecha.


================================================================================
API / DB
================================================================================

  POST /api/coupons/referral/activate
    body: panelId, guestCodigo, codePrefix?, brideName?, groomName?, …
    → crea o devuelve cupón en categoría "referido"

  SQL: scripts/009_cupones_referidos.sql
    columnas: panel_id, invitado_codigo, evento_label

  Admin cupones: categoría "Referidos · Panel invitados"
    orden de listado por created_at (activación)


================================================================================
UX TEASER / MODAL (muestra actual)
================================================================================

  Teaser (sin abrir modal):
    - título (ej. ¿Organizás tu propio evento?)
    - subtítulo: Te regalamos un cupón de 20% OFF para tu próxima invitación
    - botón: Ver cupón

  Modal:
    - Cupón 20% OFF
    - Ingresá el siguiente código cuando reserves tu invitación:
    - código copiable
    - Válido hasta el {fecha}
    - Guardá una captura de esta pantalla para utilizarlo.
    - [Ver modelos / reservar] → landing #muestras
    - [Regalar cupón] → WhatsApp con mensaje + código + link + vencimiento


================================================================================
CASOS BORDE / PROBLEMAS
================================================================================

  1) Confirmación sin código (registrarSinCodigoEnPanel / anónimo)
     → No hay cupón por invitado. El teaser NO se muestra (falta panel.codigo).

  2) Invitación abierta sin ?i=
     → Igual: no hay guestCodigo → no teaser.

  3) Preview / muestra / ?rsvpForm=1
     → Promo oculta (no activar cupones falsos).

  4) Panel con invitados aún no creados
     → No hay links; nadie puede activar. OK.

  5) Borrar invitado del panel
     → Cupón ya creado en DB sigue válido hasta usarse/vencer.
     Decidir: ¿invalidar cupones de invitados borrados? (pendiente)

  6) Varias personas de una familia (un solo codigo de grupo)
     → Un solo cupón por fila invitado, no por integrante.

  7) Prefijos largos (nombres largos)
     → truncate a 16 letras. Colisión posible entre eventos: el número
       es por prefijo global de categoría referido; si dos bodas usan el
       mismo prefijo, comparten secuencia. Mitigación futura: prefijo +
       clientRef o panelId corto.

  8) SQL 009 no corrido en Supabase
     → Activate cae a fallback en usado_nombre (ref:panel:codigo).
     Correr 009 en producción.

  9) Cupón en configurador
     → validate/redeem ya usan tabla cupones; categoría referido =
       single_use. Links a modelos aún no pre-cargan coupon= en URL
       (pendiente opcional).

 10) confirmacion por WhatsApp (plan base sin form)
     → Hoy SOLO en sección rsvp (formulario). Extender a
       confirmarWhatsapp si algún día hay panel+comun con ?i=.
